# SA Hall Material 3 design system

This file is the source of truth for the Angular UI. Explicit product requirements override generic component defaults.

## Direction and language

- Arabic is default; set `lang="ar" dir="rtl"` on the document.
- Use logical CSS properties (`inline-start`, `inline-end`) and Angular CDK directionality.
- Isolate phone numbers, email, identifiers and technical values with `bdi` or scoped `dir="ltr"`.
- Do not mirror universally recognized playback/media or brand marks. Directional arrows use semantic start/end icons.

## Color roles

Primary seed: royal violet `#5E35B1`. Tertiary seed: champagne gold `#C9A43B`. Palettes are generated by
`ng generate @angular/material:theme-color` into `apps/web/src/styles/_theme-colors.scss` and applied with
`mat.theme()`, so every Material component reads the same `--mat-sys-*` roles in light and dark schemes.

```text
role                  light      dark
primary               #6C45C0    #D1BCFF
on-primary            #FFFFFF    #3D0090
primary-container     #EADDFF    #5429A7
tertiary (gold)       #755B00    #EAC256
tertiary-container    #FFDF91    #594400
surface (page)        #FFFFFF    #15121A
surface-container-low #F8F1FC    #1D1A22
```

Application roles Material 3 does not define live beside the theme in `styles.scss`:
`--sh-success*` (green HCT palette, hue 145), `--sh-gold` (rating stars and accents), and the luxury
"ink" band `--sh-hero-ink` (`#24005B`, primary tone 10) with `--sh-hero-accent` gold for headlines on it.

Light and dark schemes are emitted as separate blocks (not `light-dark()`) so older iOS Safari renders them.
`prefers-contrast: more` applies the generated high-contrast overrides. All listed text pairs are at least
4.5:1 (gold text uses tone 40 in light, tone 80 in dark; gold icons use tone 50 at 4.25:1, above the 3:1
non-text minimum). Color never acts as the only state indicator: status pills always pair an icon with text.

## Typography

- Body, labels and data use the platform UI font (`system-ui`: SF Arabic, Segoe UI, Roboto/Noto Arabic),
  which costs zero downloaded bytes and matches each device.
- Display, headline and large-title roles use the self-hosted El Messiri variable font
  (`@fontsource-variable/el-messiri`, 22 KB Arabic subset, `font-display: swap`, unicode-range split).
  Never load Google Fonts at runtime.
- All Material 3 tracking tokens are overridden to `0`: letter-spacing breaks Arabic letter joining.
- Body minimum: 16 px / 1.65 on mobile. Use 600–700 weight for headings and 400–600 for body/labels.
- Use tabular figures (`.sh-num`) for prices, dates, counts and tables.

## Shape, spacing and elevation

- 4 px base; common spacing: 8, 12, 16, 24, 32, 48.
- Component radii: 8 px compact, 12 px controls, 16 px containers, 28 px sheets/FAB where Material specifies it. Avoid arbitrary giant radii.
- No shadows and no borders. This is a hard rule, not a default. `mat.theme-overrides` sets `level0`–`level5` to `none`, and component
  tokens with hard-coded shadows (menu, select, autocomplete, datepicker, expansion, snack bar, bottom
  sheet, button toggle) are cleared in `styles.scss`.
- The light-scheme page background is pure white (`--mat-sys-surface: #FFFFFF`). Structure comes only
  from tonal layers on that white: `surface-container-low` for cards, panels and sidebars;
  `surface-container` / `-high` for nested rows, inputs and hover; `secondary-container` for selection.
  Dividers and hairlines are not used: rows are separated by spacing, tables by alternating row tone.
- Material components are configured borderless through tokens in `styles.scss`: filled text fields
  without the resting underline (all corners rounded), tonal buttons (`matButton="tonal"`) instead of
  outlined buttons, filled cards (`appearance="filled"`), chips and segmented buttons without outlines,
  switches without track outlines, and today's date marked with a tonal fill.
- Top app bars sit on the white page and switch to `surface-container` once content scrolls under them
  (Material 3 scrolled state), which replaces a bottom border or shadow.
- Exceptions required for accessibility only: the visible keyboard focus ring, the text-field focus
  indicator, checkbox/radio control outlines, and the tab selection indicator.
- Desktop content max width is consistent per shell; operational pages prioritize useful density.

## Navigation and app behaviour

- Below 840 px every area behaves like an installed mobile app: a small top app bar plus a Material 3
  navigation bar (80 px, 64 × 32 pill indicator, filled icon on the active destination, safe-area aware).
- Public/client bar: Home, Halls, Services, My bookings, Account (five destinations maximum).
- Owner/admin bar: four primary destinations plus "More", which opens the modal navigation drawer.
  At 840 px and wider the drawer is persistent (standard navigation drawer, `mat-nav-list` active indicator).
- Pushed detail screens (hall, booking) hide the bottom bar and use a back-arrow top bar or an immersive
  photo header; checkout is a full-screen flow with a close action, linear progress and a sticky total bar.
- Destructive or consequential actions confirm in a dialog; booking details open full-screen on phones.
- The app is installable (web manifest, maskable icons, standalone display, theme colors per scheme) and
  a service worker serves the shell offline-first. Route changes use the View Transitions API, disabled
  under reduced motion.
- Deep links preserve filters (query parameters) and identifiers; current destination exposes
  `aria-current="page"`.

## Icons and imagery

- Icons are Material Symbols Rounded (weight 400) rendered as inline SVG through `<app-icon>`; outlined by
  default, filled for active navigation and accents. No icon font is downloaded. Regenerate
  `shared/icon/icons.ts` with only the names the templates use.
- Directional icons (`arrow_back`, `logout`) take the `mirror` attribute so they flip in RTL.
- Photos are local WebP renditions (`public/images/<name>-480|800.webp`, hero 640/1024/1600 plus a
  portrait crop for phones) with `srcset`/`sizes`, explicit dimensions, lazy loading below the fold and
  `fetchpriority="high"` for the first visible image.

## Components and data

- One primary action per view; secondary actions are visually subordinate.
- Data-heavy views use semantic tables, sticky headers only when helpful, sortable headers with `aria-sort`, pagination, filter summary and overflow action menus.
- On mobile, prioritize columns or use a purpose-built list; never force unreadable horizontal tables.
- Forms use visible labels, typed inputs, field-level Arabic error text, error summary for multi-error submissions and focus to the first invalid field.
- Destructive actions require clear confirmation; reversible removal offers undo where safe.
- Empty states explain what happened and the next useful action. Errors include recovery/retry.
- Loading under 300 ms does not flash; longer work uses reserved-space skeletons or progress.

## Interaction and accessibility

- Minimum target: 48 x 48 CSS px; minimum 8 px separation.
- Every icon-only button has an accessible Arabic name and tooltip where useful.
- Visible keyboard focus is never removed. Tab order follows reading order.
- Add a skip-to-content link and appropriate landmarks/headings.
- Snackbars use `aria-live="polite"`; blocking errors use appropriate alert semantics without stealing focus unexpectedly.
- Images have meaningful Arabic alternatives or empty alt when decorative; dimensions/aspect ratio reserve layout space.
- Support zoom and text growth without clipping at 200%.

## Motion

- State feedback: 150 ms; standard transitions: 200–250 ms; sheets/dialogs: up to 300 ms.
- Animate only opacity and transform; never animate layout dimensions for decoration.
- Motion communicates state/navigation and remains interruptible.
- Under `prefers-reduced-motion: reduce`, remove non-essential transition/animation and smooth scrolling.

## Prohibited patterns

- Box shadows, drop shadows, borders, outlines, hairline dividers and random gradients
- Card grids for ordinary table data
- Emoji as structural icons
- Placeholder-only labels, hidden focus, color-only statuses
- Remote placeholder/demo assets in production paths
- Decorative charts without a decision-making purpose and accessible table/summary
- Duplicated headings/descriptions or large empty hero spacing in operational views

## Responsive verification

Verify at minimum 375, 768, 1024 and 1440 CSS px, portrait and landscape where applicable. There must be no page-level horizontal scrolling, content behind fixed navigation, hover-only actions, or RTL regressions in menus/dialogs/pagination/date controls.
